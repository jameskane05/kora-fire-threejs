WGSL: stores to nested function-scope array lost when outer loop contains two dynamic inner loops

A @compute shader writes D[i] once per iteration of a for (i = 0; i < 6; i++) loop. When the loop body also contains two inner loops with data-dependent bounds (j < i, k < i) and a nested array (array<array<f32, 6>, 6>) is accessed, only the final iteration's store to D survives. Expected D = [57600 x6]; WebKit produces D = [0, 0, 0, 0, 0, 57600]. Chrome (Tint/Dawn) produces the correct result for the same shader. Flattening the nested array to array<f32, 36> avoids the bug.
